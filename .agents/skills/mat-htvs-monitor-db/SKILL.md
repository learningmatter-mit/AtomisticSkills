# HTVS Monitor: DB

**Goal**: Periodically check the status of submitted HTVS jobs, report progress, and automatically parse results into the database once calculations are finished.

## Configuration & Safety (CRITICAL)

Wait! HTVS operations directly interact with research databases. Before running any commands:
1.  **Expose the Context**: Explicitly state the `settings_module` and `group_name` you are about to use.
2.  **Request Confirmation**: Ask the user: *"I am about to perform this operation on the [GROUP_NAME] project within the [SETTINGS_MODULE] database. Is this correct?"*
3.  **Do NOT proceed** until the user gives explicit approval.
4.  **Verify Tracking Files**: This skill reads `htvs_request_job_tracking.json` to identify Job IDs.

## Workflow

1.  **Request Jobs**: Use the standard HTVS skills to submit your calculations.
2.  **Start Monitoring**: Run the `monitor_htvs_db.py` script.
3.  **Automatic Parsing**: If `completed_path` is provided, the script will trigger `htvs_parse_jobs` upon completion.
4.  **Resuming**: If the agent is interrupted, simply run this skill again; it will pick up the list of IDs from the local tracking file.

## Usage

### Monitor Jobs for current Group
```bash
# Env: htvs-agent
python .agents/skills/mat-htvs-monitor-db/scripts/monitor_htvs_db.py --poll_interval 300
```

### Options
- `--group_name`: Override project group (default: from context).
- `--poll_interval`: Seconds between checks (default: 300). For 40m-2h jobs, 300s (5 minutes) is recommended to balance responsiveness and database load.
- `--auto_parse`: Set to `True` (default) to trigger `htvs_parse_jobs` on completion.
- `--completed_path`: Path to completed jobs directory on the cluster.

## Constraints
- **Environment**: Requires `htvs-agent` conda environment.
- **State**: Relies on the JSON tracking files generated by `htvs_server` MCP tools.
